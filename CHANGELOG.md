# Changelog

## 1.1.37 — 2026-09-03

### Changed

- **Step 10's mechanical-sweep routes now use atomic directives** ([#38](https://github.com/jbaruch/blog-writer/issues/38)) — the Exit 0, Exit 1, and Exit 2 bullets previously bundled interpretation, reading, rewriting, rerunning, and reporting actions. Splitting those actions makes each route scannable while preserving the context-verification exception that protects prose from rewrites based on split sentence artifacts. The script-invocation preamble also drops implementation rationale already archived in the changelog and keeps only its two directives.

## 1.1.36 — 2026-09-01

### Fixed

- **Shared writing identities are established and discovered before first-use selection**
  ([#51](https://github.com/jbaruch/blog-writer/issues/51)) — v1 creators named
  `~/.claude/blog-writer-identities/{personal,corporate}/<name>/` as a default but owned no
  lifecycle for the shared root. On a machine whose legacy persona already lived in Google
  Drive, a Port corporate identity fell back into the first blog project's `_blog-skill/`
  directory. A tested setup tool now probes or establishes the canonical directory or its
  user-selected symlink, reports dangling links and occupying files without replacing them,
  prepares both package directories, and discovers a legacy persona without modifying it.
- **A clean blog project offers validated shared packages instead of silently taking the
  legacy fallback** — first use enumerates manifest-valid personal and corporate candidates,
  rejects malformed and escaping entries, asks for personal selection at every candidate
  count, and keeps corporate selection explicit. Confirmed selection is written only after
  every resulting package resolves. The next session treats that schema-v2 project record
  as authoritative and performs no rediscovery.
- **Legacy migration now compiles into shared storage without rewriting its source** — the
  former migration contract added v1 files directly to the legacy directory, including
  through an established legacy symlink. The legacy package is now a read-only source for a
  new personal identity, preserving its path, target, and original files.

## 1.1.34 — 2026-09-01

### Added

- **Personal identity creation is self-contained and correction-driven** — the creator now
  carries the v1 manifest and provenance contract in its own instructions, recognizes
  natural requests about tone and writing style, and re-presents corrected conclusions
  beside their cited sources before approval. It also owns an explicit legacy v0-to-v1
  rewrite that preserves the old files, excludes mixed product context from personal
  resources, and requires approval before selection.
- **Corporate identity creation has an explicit correction loop** — consequential creates
  and updates stay in `draft` while the user reviews the summary, guidance, inferences, and
  unresolved items. Rejected or corrected conclusions are revised, traced back to their

Either layer can stand alone, and assignment instructions plus verified facts remain above both.
- **Two creator skills compile heterogeneous sources into a shared, provenance-aware package** — `create-personal-identity` and `create-corporate-identity` preserve source authority, distinguish explicit rules from observed patterns, keep contradictions visible, and require user approval before an identity becomes reusable.
- **A tested resolver and configuration writer own identity selection** — project configuration represents personal-only, corporate-only, and combined modes without accidentally activating a legacy persona. Selection schema v2 rejects new named-user paths; the writer migrates resolvable v1 values to absolute paths while the resolver remains dual-read. Resource roles survive shared-file declarations, paths stay inside each identity package, and the legacy `~/.claude/blog-writer-persona/` remains the fallback only when a project has no explicit selection.

## 1.1.31 — 2026-08-30

### Changed

- **The pattern count lives in the pattern file, and nowhere else** — `39` was written into 22 places: `PATTERNS_TOTAL` in `sweep.py`, a literal assertion in `tests/test_sweep.sh`, and 20 prose statements across `SKILL.md`, `README.md`, `process.md`, `structural-audits.md`, `tone-guide.md` and `ai-anti-patterns.md` itself. Adding a pattern meant editing all of them, and the one that mattered most was the one nobody would think to check: `.coverage.note` tells the agent how much of the check went unexamined, so a stale total there understates the gap in the exact sentence written to prevent that. `sweep.py` now counts the `## <n>. ` headings in `references/ai-anti-patterns.md` on every run, and the prose says "every pattern" or "the catalog" instead of a number. Adding a pattern is now one edit to one file.
- **A total that cannot be counted is a run that reports nothing** — the count happens before the sweep, and a missing or heading-less pattern file exits 2 with a diagnostic naming the cause, rather than falling back to a guess. Falling back would produce the same silently-wrong coverage figure the change exists to remove.
- **The floor sits strictly above the sweep's own examined count, not at zero** — this script's contract is that it covers a minority of the catalog, and a catalog no larger than the sweep breaks that in two directions. At exactly six the note reports zero unexamined while `not_run_judgment` still names seven sweeps that did not run; below six the arithmetic goes negative, and a three-pattern file reported "-3 of the 3 patterns were not examined". Rejecting only an empty file left both emitting structured nonsense, which is worse than emitting nothing. Both bounds were review findings on #43, where the first derivation test asserted the negative output as a success.
- **Every way the catalog read can fail exits 2** — the first version caught `OSError` alone, so a pattern file present but not valid UTF-8 escaped as a traceback where the contract promises exit 2, and an `OSError` whose `strerror` is `None` rendered the cause as "None". Both were review findings on #43.
- **The suite reads the total the same way the script does** — `tests/test_sweep.sh` derives the expected figure from the shipped file rather than asserting `39`, so the assertion cannot rot into a second stale copy. Three new cases cover the derivation itself: a script running beside an eight-pattern file reports eight, and a catalog that cannot be counted exits 2 in each of its shapes — no numbered headings, no more patterns than the sweep examines, exactly as many as the sweep examines, not valid UTF-8, absent — each checked for the actionable half of its diagnostic. 70 assertions, up from 64.
- **What stays a literal:** `PATTERNS_EXAMINED = 6`, which is this script's own coverage rather than a fact about the catalog, and every `#39`-style pattern reference in prose, which is an identifier and not a count.

## 1.1.30 — 2026-08-30

### Fixed

- **Every script invocation in `SKILL.md` names its interpreter** — tessl materializes a plugin's files without the executable bit. The scripts are `rwxr-xr-x` in this repo and `rw-r--r--` under `.tessl/plugins/jbaruch/blog-writer/skills/blog-writer/` in a consumer, so all six invocations, each printed as a bare path in a `bash` fence, came back `permission denied` when an agent ran the command exactly as written. The symptom reported was the Step 5 Wikipedia refresh failing, but that step is only the first one an agent reaches after onboarding; the same break covered the persona probe (Steps 2 and 3), the shape-convergence audit (Step 8), the counting sweep (Step 10), and the shape record (Step 12). Reproduced against a 1.1.29 install in a consumer repo, where `bash <mount-path>` and `python3 <mount-path>` both run clean. Each invocation now carries `bash` or `python3`, and the preamble states the rule so a later edit does not drop a prefix back to a bare path.
- **The prefix is safe for the scripts that need their own location** — `check-shape-convergence.sh` and `record-post-shape.sh` resolve `SCRIPT_DIR` from `BASH_SOURCE[0]` to source `post-shapes-lib.sh`, and every script gates `main` on `[ "${BASH_SOURCE[0]}" = "${0}" ]`. Under `bash <path>` both variables hold that path, so sourcing and the entry-point guards behave as they do under a direct execution. `sweep.py` keeps its `#!/usr/bin/env python3` shebang and runs the same way under an explicit `python3`.
- **The skill does not depend on the installer's mode bits** — restoring the executable bit at materialization time is tessl's to decide, and a fix there would not reach the installs already on disk. Naming the interpreter works under either behavior.

## 1.1.29 — 2026-08-22

### Fixed

- **The publish pipeline can run the Python gate it was given** — 1.1.28's `.github/lint-python.sh` needed `ruff` and `pyright`, and only `test.yml` installed them. `publish.yml` calls the reusable publish workflow, whose `pre-publish-script` runs `.github/pre-publish.sh` on a runner that installs nothing, so the gate exited 2 on the missing engines and the publish step skipped. The gate behaved correctly — it failed loudly and shipped nothing rather than publishing unverified, and the registry never advanced — but no merge to `main` could publish while it stood. `publish.yml` now requests the Python and Node runtimes from the reusable workflow, and `.github/pre-publish.sh` provisions the engines on top of them when running in CI.
- **Every input the publish call passes is declared by the revision it pins** — the first attempt at the above read the input list from the reusable workflow's default branch and passed `node-version`, which the pinned revision did not declare. A caller passing an undeclared input fails the run at startup, before any job is scheduled, so the publish came back `startup_failure` with zero jobs and no step log — it presents as an Actions outage rather than as the caller error it is, and the only way to see it is to diff the caller's inputs against the pinned revision's declarations rather than the default branch's. The pinned ref moves to `f96cd07`, which declares `node-version`, so the input and the bump land together; Dependabot's weekly github-actions scan is that pin's renewal mechanism. Node is pinned rather than taken from whatever `ubuntu-latest` ships, per `dependency-management` Pinning.
- **The engine pins live in one place** — `.github/install-python-gate.sh` holds the `ruff` and `pyright` versions and installs them idempotently. They were env vars on a `test.yml` step, which is why the publish path had no way to reach them; a second copy would have let the two pipelines gate the same code with different engines. `test.yml` and `.github/pre-publish.sh` both call the script now. The quarterly renewal cadence moves with the pins.
- **The installer is held to the same standards as every other script here** — it shipped with its workflow at file scope and no tests, both of which this repo requires of the scripts it already had. It now runs through `main()` behind a `${BASH_SOURCE[0]}` guard so it can be sourced without installing anything, and `.github/tests/test_install_python_gate.sh` covers the idempotent path, each missing installer, each installer failure, an install that reports success without putting the tool on PATH, and the guard itself. Every engine and installer is a stub on a suite-owned PATH, so no case reaches a package index; stub invocations are logged, so "nothing installed" is asserted rather than assumed. `.github/run-script-tests.sh` discovers suites under `.github/` as well as `skills/`.
- **The pin is verified after installing, not just before** — post-install checking asked only whether each executable existed. An installer can exit 0 while an older executable stays ahead on PATH (a distro package, a stale shim), and presence alone reported that as pinned tooling while handing the gate the wrong engine. Both engines are now re-checked against the pin after installing, with a diagnostic naming what they actually report. The suite's mismatch cases had encoded the hole — their stubs kept reporting the old version after "installing" and still expected success — so engine stubs now read their version from a file the installer stub rewrites, which is what separates an install that took effect from one that silently did not.
- **The version check is exact, not a substring** — `grep -qF 0.9.5` accepts `0.9.50`, a different release, so a mismatched engine would have been left in place and reported as pinned. The check now compares the complete version token, with the near-miss as its own regression test. The suite reads the pins out of the script rather than restating them, so a bump cannot strand it on the old values.
- **A developer's machine is not silently modified** — the CI install is conditional on `GITHUB_ACTIONS`. Locally the gate still fails with the exact command to run, since an unasked global install is intrusive and skipping the engines is not an option in either place (`ci-safety` Install, Don't Skip).

### Added

- **The counting half of the Pass 1 anti-pattern check runs as a script** (#35) — `skills/blog-writer/sweep.py` implements fragment chains (#3/#4), paired em-dashes (#7), em-dash density (#8), low burstiness (#14), and unicode giveaways (#18). `process.md` Phase 3 had specified eleven "mechanical sweeps" as prose for the agent to reproduce, which `jbaruch/coding-policy: script-delegation` forbids for fixed-input/fixed-output work: roughly 120 literal searches and a per-sentence word count of the whole draft, performed by reading. The approximation was silent — nothing distinguished "ran the sweep, clean" from "did not run the sweep." In the session that filed the issue the agent read 12 of the 39 patterns, cited pattern numbers it had never opened, and reported "anti-pattern check: clean" three times, while a #7 paired em-dash it had introduced during its own humanization pass (`Three facilities — Austin, Berlin, Osaka — where...`, replacing correct commas from an earlier draft) survived to the author's eye. Writing the sweep as a script found it in one run, along with a #14 burstiness regression the agent had introduced while fixing an unrelated note.
- **Five of the eleven, not eleven** — the split is counting versus judging, not pattern-by-pattern taste. A counting sweep's verdict falls out of an arithmetic result with no reading involved, and that is where a model is structurally worse than a script: uniform sentence length is invisible when reading for content and obvious when counting. The other six are semantic tests wearing a watchlist. #10 and #35 are defined by the delete test ("if the phrase can be deleted without changing the meaning, delete it"), #36 by the interchangeability test, #17 by whether two noun phrases denote one concept, #32 by whether two numbers make the same point, and #1 by whether a "rather than" joins two candidates for the same slot. #12's watchlist carries 26 usage qualifiers across roughly 70 terms — `"key" (as adjective)`, `"navigate" (abstract)`, `"rich" (figurative)`, `"highlight" (as verb)` — and the qualifier is the check: in a post about API key rotation a script flagging `key` produces noise, and noise gets ignored.
- **The issue's proposal to parse the watchlists from `ai-anti-patterns.md` was dropped**, and counting-only makes the question moot — no watchlist in the script means no parsing, no drift test, no sync problem. It would not have survived the file either. Pattern #12's section holds 120 quoted strings against a ~70-term watchlist and #10's holds 62 against ~35; the excess is the *good* examples, quoted identically to the bad terms (`"Deploy time went from 45 minutes to 90 seconds." (not "dramatically improved")`), so a naive parser adds the cure to the watchlist. The `**The watchlist:**` marker appears in #12, #35 and #36 but not #10. And one of the two drift channels the issue cited does not exist: `fetch-signs-of-ai-writing.sh` downloads the Wikipedia article to a temp path for the agent to read and never writes into `ai-anti-patterns.md`.
- **The report names its own coverage on every run and never prints a bare `clean`** — the inverse failure, documented on the same issue. After the script existed in draft form, a `#30` faux-insight setup ("Here is the part everyone skips:", a named structural variant verbatim except one word) shipped in a CFP abstract because "script says clean" had displaced the contextual read. A tool that covers 6 of 39 patterns and prints `clean` invites exactly that, since `clean` reads as "the check passed" rather than "six of thirty-nine passed." Every run now lists the five sweeps that ran, the seven judgment patterns that did not, and the count of patterns left unexamined.
- **Markdown is parsed rather than treated as flat text**, and each exclusion is a correctness fix. Fenced code, frontmatter, and `<!-- VERIFY: ... -->` markers are draft machinery, not prose. Headings are not sentences, and counting them inflates the short-sentence runs #3/#4 looks for. Asset placeholders (`[Screenshot 01: ...]`) are markers. List items and table rows are excluded from #3/#4 and #14 only: a list of five three-word items is a list rather than a fragment chain, and parallel list items are supposed to be uniform in length, so both sweeps would fire on every post containing a list. The em-dash and unicode sweeps still cover list text, since an em-dash in a list item is still an em-dash. #7 matches per sentence and, in a list, per item — matching across a whole block paired the trailing dash of one list item with the leading dash of the next, which is how the repo's own README produced a phantom finding during development. #18 runs over the same parsed blocks rather than the raw file, so a bullet character in a fenced code sample or a curly quote in a `<!-- VERIFY -->` marker is not a prose tell; it still covers headings and list items, which the reader sees. The sentence splitter guards abbreviations and lone initials but deliberately carries no digit guard: the split pattern already requires whitespace after the period, so a decimal never reaches it, while "It failed at 4. 3 people knew." is two real sentences that a digit guard merges — suppressing exactly the fragment-chain and burstiness findings the script exists to catch.
- **stdout is a JSON object, the only format** — `script-delegation` Script Requirements makes scripts JSON-producing, and a second human-readable mode would have been a second contract to keep true. The object carries `hits[]` with `pattern`, `label`, `line`, `detail` and `context`, plus a `coverage` object holding `ran`, `not_run_judgment`, `patterns_examined`, `patterns_total` and a `note` stating in words how many patterns went unexamined. Coverage is present on a zero-hit run, which is the point: an empty `hits` reads as "the check passed" when it means "the counting half passed". Rendering findings for the author is the skill's job, not the script's.
- **A block splits where its structure changes** — a blank-line-delimited group was labelled a list if any line in it looked like a list item, and markdown lets prose run straight into a list with no blank line between them. That put the prose in a list block, and the sentence sweeps skip lists, so a fragment chain sitting immediately above a list went unreported. Groups now split into runs of a single kind. A prose line *following* a list, table, or quote is the opposite case — markdown reads it as a lazy continuation of the item above — so it stays with its segment, which keeps a wrapped list item whole rather than shattering it into one-line fragments.
- **Every excluded region is recognised by a real grammar, not by a lookalike** — three more ways a malformed draft could sweep clean while examining nothing. Frontmatter matched any later `---`, so a document opening with a thematic break and carrying a second one hid every line between them; it now needs a YAML key on the line after the delimiter and every non-blank line up to the closer still looking like YAML, which is what separates frontmatter from a thematic break. A fenced block closed on any fence-looking line, so a ``` opener closed on ~~~ or on a shorter run of its own character; per CommonMark the closer now matches the opener's character, runs at least as long, and carries no info string. And an unterminated `<!--` was tracked as state that never cleared, making every later line transparent; only the closed form is matched now, so a stray `<!--` stays ordinary content. Each has a control test proving the properly-closed form is still excluded.
- **A region is excluded only when it closes** — a draft whose first line was `---` with no second one, or which opened a fence it never terminated, had every later line marked transparent. No blocks meant no findings, so the script exited 0 having examined nothing: a false clean, the worst outcome it can produce and the one it exists to prevent. Frontmatter and fences are now recognised only as closed pairs, so an unterminated fence is a typo whose content still reads and a leading `---` is the thematic break it actually is. Closed regions are excluded exactly as before, with a control test proving it.
- **Which hits need a second look is emitted, not restated** — the exit-1 route named the sweeps whose findings rest on sentence segmentation, which is a per-tier classification rule `script-as-black-box` keeps in the script. Each hit now carries `verify_context`, set by the sweep that produced it, and the skill routes on the field: fix every hit, and where the flag is true read the `context` first in case the split shown there is an artifact. The classification lives once, where the sweeps are defined, so adding a sweep cannot leave the skill describing the old set.
- **`process.md` points at the coverage contract instead of copying it** — the Pass 1 procedure enumerated the counted patterns with a description each, duplicating what the run reports in `.coverage.ran` and what `ai-anti-patterns.md` already defines. The counting half now names what kind of work it is and points at the script's decision contract and the run's own output; the judging half keeps its per-pattern instructions, since the delete test, the interchangeability test, and the term inventory are the agent's procedure and live nowhere else.
- **The exit-1 route no longer calls every hit definitive** — the skill said each hit is a finding rather than a candidate, while the script documents that ambiguous sentence boundaries deliberately split rather than merge, producing the occasional false fragment for the agent to dismiss. Step 10 then told the author to fix all of them, which is an instruction to edit valid prose. The route now separates the two: `#7`, `#8` and `#18` count punctuation and characters and are definitive, while `#3/#4` and `#14` count sentences and carry the hit's `context` to be read first.
- **The three CI gates check their own discovery** — each enumerated its files through a process substitution, whose exit status the parent shell discards, so a `find` that failed part-way would hand the gate a short list it then reported clean. Silent under-checking in the gates that exist to prevent silent under-checking. Discovery now runs in a command substitution whose status is checked. Two of the three predate this change and are fixed here rather than left, since a round was already in flight.
- **Excluded regions are transparent, not deleted and not blanked** — three line roles rather than two, because both simpler options are wrong in opposite directions. Deleting an excluded region collapses its newlines, which shifts the reported line of every later finding and concatenates the prose on either side of a multi-line comment onto one line. Blanking it preserves the numbering but turns that comment into a paragraph break, splitting a paragraph the author wrote as one and losing the fragment-chain or burstiness finding inside it — the exact failure the script exists to prevent. A transparent line holds its number without being either content or a separator, so `It failed. We knew.` / a two-line `<!-- VERIFY -->` / `Nobody cared.` stays one paragraph and still reports its chain at the author's line 1. An inline comment is removed without breaking the sentence around it.
- **Three narrowings that would have shipped as silent misses** — each was the script quietly checking less than it claimed, which is the failure the whole change exists to prevent. The sentence splitter treated every sentence ending in a lone capital as an initial, so "Pick A. Go. Stop." merged at "A." and took its fragment chain with it; the guard now fires only inside a genuine run of initials, which is enumerable where "detect an initial" is not (`script-delegation` The Regex Trap). Blockquotes were classified, handled by the splitter, and then dropped from #3/#4 and #14 by a `kind != "prose"` filter, though nothing documented them as excluded; they are reader-visible prose and now read as prose, wrapped across lines with their markers stripped rather than cut at each line break. And #7 capped the text between a pair at 80 characters, which exempted exactly the long asides that are the pattern's most characteristic form ("The system — a Rails monolith running on three boxes in a colo nobody remembers renting — fell over"); per-sentence matching, not a length limit, is what keeps two unrelated asides from reading as one pair.
- **A run of initials survives whole, its last initial included** — the first attempt protected an initial only when another followed it, which left "J. R. R. Tolkien" splitting before the surname into `[4, 1, 1, 5]` and reading as a six-sentence fragment chain. Since Step 10 tells the author to fix every hit, a false one costs real edits. The guard now protects the span of any run of two or more initials. Two is the threshold that keeps this enumerable: a single lone capital before a period is genuinely ambiguous ("A. Smith wrote it." against "Pick A. Smith wrote it."), no regex settles it, and pretending otherwise is the Regex Trap. The single capital stays unprotected, so "Pick A. Go. Stop." still ends three times.
- **Both remaining splitter guards fail toward a false split, never a merge** — a false split inflates the count of short sentences and surfaces as a #3/#4 hit the agent dismisses, while a merge silently removes a finding. The bias is now stated in the code beside the guards, since the two bugs above were both merges.
- **Every finding points at its own line** — a hit inside a list names the item's line rather than the block's, and a hit inside a wrapped paragraph names the line the sentence starts on, mapped back through the block's retained source numbering. Raised by Copilot as an advisory and folded into a round already in flight (`boy-scout`).
- **`.github/lint-python.sh` gates the new language** — `ruff format --check`, `ruff check`, then `pyright` at zero findings, in the order `code-formatting` and `language-diagnostics` require, chained into both `test.yml` and `.github/pre-publish.sh` beside the existing ShellCheck gate. `pyproject.toml` pins the target version so a finding cannot appear or vanish with the runner image. Python rather than bash for this one script: sentence segmentation needs lookbehind, which bash ERE lacks, and the unicode sweep counts characters where bash counts bytes. The five existing scripts stay in bash, so the language boundary is by job — environment plumbing in bash, text analysis in Python — rather than by accident.
- **`tests/test_sweep.sh` covers the contract, not the implementation** — every exit code, the coverage statement on a zero-hit run, the assertion that no judgment pattern is ever reported as a hit, each threshold at and above its limit, every markdown exclusion, the abbreviation guard (a false split on "e.g." would manufacture a fragment chain), and the cross-item em-dash regression. Fixtures are written programmatically into a suite-owned temp directory, so the suite touches no network, clock, or randomness.

### Changed

- **`process.md` Pass 1 is recategorized, which is the root cause the issue attributed to the agent** (#35) — all eleven sweeps sat under one heading, "do a dedicated mechanical sweep instead of relying on contextual reading alone," while six of them were semantic tests. The document taught that a string scan discharges the check, so both failure directions follow from it: a vibe read replacing the mechanical sweep, and the mechanical sweep replacing the contextual read. Pass 1 now splits explicitly into "the counting half, which the script does, not you" and "the judging half, which no script does," with each judgment pattern naming the test that decides it. No instruction was dropped; the literal searches for #1, #10, #12 and #35 remain, reframed as locating candidates the agent then judges.
- **The counting sweeps' figures live only in the script** — `process.md` had restated them ("under six words", "3+ consecutive", the paired-em-dash match), which `script-as-black-box` forbids because copies drift: changing a constant would have left the reference lying. The procedure keeps what is its own — what each pattern is and how to fix it — and points at the named constants under "Decision contract" at the top of `sweep.py` for the figures, and at `ai-anti-patterns.md` for the pattern definitions those constants implement.
- **The exit-0 route names both halves of what went unchecked** — `not_run_judgment` holds the seven sweeps that look mechanical and are not, which is 7 of the 33 patterns the script leaves unexamined. Routing the agent through that field alone read as an exhaustive list and would have licensed skipping the other 26.
