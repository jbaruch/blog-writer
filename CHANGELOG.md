# Changelog

### Changed

- **Migrated the plugin manifest from `tile.json` to `.tessl-plugin/plugin.json`** — the legacy `tile.json` form is retired; `summary` becomes `description` and the `skills` map becomes an array. Reconciled the residual "tile" wording to "plugin" across the publish workflow's display name, `references/ai-anti-patterns.md` examples, and `evals/scenario-7/criteria.json`. The `docs.tessl.io` page references in `example-persona/product.md` keep "tiles" — those are live external URLs and page titles. Also dropped the forbidden `## Unreleased` heading so the publish pipeline's stamp step heads these entries with the published version.
- **Wired the CHANGELOG stamp step into the publish pipeline** — `publish.yml` now passes `stamp-changelog: true` to the reusable workflow, whose input defaults to `false`. The step had been silently skipping on every publish, which is why entries accumulated under an `## Unreleased` heading that `context-artifacts.md` forbids: with auto-bump assigning the version at publish time, a PR author cannot write the heading, and un-headed blocks are illegal when nothing stamps them. The stamp action mirrors `tesslio/patch-version-publish`'s version computation, so the heading it writes matches the version actually published.

- **Moved the skill under `skills/blog-writer/`** — `SKILL.md`, `references/`, and `example-persona/` now live in the skill directory the manifest declares, and `plugin.json` declares `"skills": ["skills/blog-writer"]` in place of the root `SKILL.md` path the migration carried over from `tile.json`. Every internal reference is skill-relative and moved with it, so no path text changed. `persona/` is unaffected — it is shorthand for the absolute `~/.claude/blog-writer-persona/`, not a repo path.

- **Restructured `SKILL.md` into flat numbered steps** — the workflow now runs as `## Step 1` through `## Step 7` with explicit continuations, per `skill-authoring` Step Structure. The relocation into `skills/blog-writer/` brought the file inside that rule's `applyTo` scope for the first time; at the repo root it had never been subject to it. Post shape and series handling moved to `references/blog-anatomy.md`, keeping SKILL.md an execution plan rather than a reference manual. No instruction text was dropped.
- **The fetch script no longer strands its temp file on failure** — when it creates the destination itself, every failure path removes it before exiting; a caller-supplied path is left alone, since deleting a file the script does not own would destroy content on a failed fetch. The test suite asserts no default-named temp file survives the run.
- **README claimed 32 anti-patterns in a second place** — the re-audit line still said 32 after the first count was corrected to 38.
- **The persona check moved into the script too** — `setup-persona-dir.sh --probe` reports `exists`, `kind` and `voice_ready` as JSON without writing anything, so the skill routes on that result instead of running its own filesystem checks. `voice_ready` is the distinction that matters: a directory can exist while onboarding never finished, and only a non-empty `voice.md` means the voice profile is real.
- **Persona bootstrap split into three steps** — probing, establishing the directory, and running onboarding were one step doing four things. They are now Steps 2, 3 and 4, each a single action, with Step 2 routing forward to whichever step the probe result calls for.
- **Stated a renewal cadence for the ShellCheck pin** — no scanner tracks a version embedded in a workflow step, so the pin now carries an explicit quarterly review cadence beside it rather than "when upstream releases".
- **Test suites no longer leave temp roots behind** — three cases built their targets as children of anonymous `mktemp -d` roots and cleaned up only the child, orphaning an empty directory per run. The roots are tracked and removed.
- **Persona directory setup moved into a script** — `skills/blog-writer/setup-persona-dir.sh` replaces the inline `ln -s` the skill told the agent to reproduce, per `script-delegation`. It creates the canonical path as a directory or as a symlink to a chosen location, reports the outcome as JSON, and is idempotent: an established persona is reported `unchanged` and never repointed, so re-running cannot orphan an author's voice profile. A dangling symlink or an occupying file is reported rather than replaced. Covered by 26 assertions in a new suite that isolates `HOME`.
- **The anti-pattern check procedure moved to the reference it governs** — Step 8 carried a nested numbered procedure, which `skill-authoring` flat numbering forbids. The three rules now open `references/ai-anti-patterns.md` under "Running the check", where the file they talk about actually is, and Step 8 points at them.
- **Each writing phase is now its own step** — `SKILL.md` Step 5 had delegated the whole five-phase workflow as a single step. Phases 0-4 are now Steps 5-9, each with its own gate and continuation, ending at a terminal Step 9.
- **The interrupt test synchronises deterministically** — it had polled with real sleeps to decide when to signal, making it dependent on scheduling and the wall clock. The stub now announces itself over a FIFO, so the signal is sent on a genuine happens-after edge. It also asserts the exact signal-derived exit status (143) rather than swallowing every `wait` failure with `|| true`, and the suite no longer suppresses any diagnostic — the last two `2>/dev/null` uses are gone too.
- **Placeholder handling moved into the phase workflow** — `SKILL.md` had Steps 6 and 7 running inside Step 5 and then returning to it, so the numbered steps were not forward-only. Identification and author confirmation now live in `references/process.md` Phase 3 beside the placeholder conventions they belong with, and SKILL.md ends at a terminal Step 5.
- **The fetch script cleans up under any exit** — cleanup ran only on explicit error branches, so an interrupt or an unexpected failure in `wc`, `tr`, `mv`, or `jq` stranded the staging file. An EXIT trap now covers every exit path, with ownership released once the file becomes the caller's. A test kills the script mid-fetch and asserts nothing is left behind; verified that it fails when the trap is removed.
- **CI installs its tooling instead of assuming it** — per `ci-safety` Install, Don't Skip, the workflow installs jq and curl and pins ShellCheck to an upstream release rather than relying on whatever the runner image ships.
- **Added `.tesslignore` so tests stay out of the published plugin** — without one, `skills/blog-writer/tests/` was part of the published surface, putting a test-only executable in every consumer's install. Verified with `tessl plugin pack`: the packaged file list loses exactly the test suite and keeps every runtime file (SKILL.md, references/, example-persona/, the fetch script).
- **A ShellCheck gate runs before the tests** — `.github/lint-shell.sh` lints every shell script in the repo and runs as its own CI step ahead of the suites, per `language-diagnostics` (diagnostics at zero findings before tests) and `code-formatting`. `.github/pre-publish.sh` chains the same two gates for the publish pipeline, and both are the commands to run locally before handing work off. `actions/checkout` is pinned to a full commit SHA, renewed by the committed Dependabot config.
- **Script tests now run in CI** — `.github/workflows/test.yml` runs every `skills/**/test_*.sh` suite on each pull request and on `main`, and `publish.yml` wires the same gate as the reusable workflow's `pre-publish-script`, so a script whose tests fail cannot reach the registry. The gate discovers suites by glob, so a suite added later needs no workflow edit.
- **The fetch is atomic with respect to its destination** — `curl` truncates its output target as soon as it starts writing, so pointing it at a caller-supplied path destroyed an existing file before the status and size checks ran. The download now lands in a script-owned staging file beside the destination and is moved into place only after every validation passes. A failed fetch leaves an existing file byte-for-byte intact, which the suite asserts.
- **Added tests for the fetch script** — `skills/blog-writer/tests/test_fetch_signs_of_ai_writing.sh` covers the success path and every documented failure exit, stubbing `curl` on `PATH` so the suite is deterministic (no network, clock, or randomness). Includes a regression test for a JSON-escaping bug the first version shipped: the result line was built with `printf`, so a destination path containing a quote produced output that did not parse. The path now goes through `jq` as a real encoder.
- **Moved the Wikipedia freshness fetch into a script** — `skills/blog-writer/fetch-signs-of-ai-writing.sh` replaces the inline `curl` and the instruction to improvise piping, per `script-delegation`. It carries a documented input/output contract and distinct exit codes: 0 fetched, 1 fetch failed (proceed with the anti-pattern file as-is), 2 tool or usage error. Failures surface a stderr diagnostic instead of being swallowed.
- **README stated 32 anti-patterns; there are 38** — corrected, and added the Tessl registry badge, a skills table, and installation instructions required by `context-artifacts` Plugin Structure. The manifest `description` is condensed to one sentence, retaining every discovery and trigger term.

### Fixed

- **Pattern #1 missed the "X rather than Y" variant** (#22) — the reference covered "Not X, but Y" and "Not just X, but also Y" but not the comparative form, which does identical structural work (negation plus affirmation competing for one slot) while reading as measured prose. It is the hardest of the three to catch by eye, because it does not sound like a mic drop. Added the variant to pattern #1 and a literal "rather than" sweep to the Pass 1 mechanical checks.
- **Pass 1 had no mechanical check for pattern #7** (#5) — only #8's em-dash density count existed, so paired em-dashes collapsed into "too many em-dashes" and individual occurrences survived all three passes. Added a #7 sweep that flags every ` — X — ` pair regardless of count, and made #8's entry state that it is the density check only, so a passing count no longer reads as clearing #7.
- **Eval scenario-2 (voice-profile onboarding) was scoring 0/0** — its output spec and all 11 criteria targeted the absolute `~/.claude/blog-writer-persona/` path, which the eval grader (working-directory only) cannot see, so every criterion failed in both baseline and with-context. Redirected outputs to the working directory; the scenario now grades real output (baseline 91 → with-context 100).

### Removed

- **Retired four no-lift eval scenarios** per `jbaruch/coding-policy: plugin-evals` ("lift, not attainment"), confirmed across two runs: the `blog-writer-framework-override` scenario (contrived, near-zero lift), and scenario-1 / scenario-5 / scenario-6 (anti-pattern cleanup, soul check, tightening) whose baselines run 94–99% — coincidence with universal competence, no headroom for the plugin to show lift. Kept scenarios (0, 2, 3, 4, 7, 8) all contribute positive lift.

### Added

- **Optional `persona/framework.md` for post-level voice overrides** — A persona can now ship a `persona/framework.md` declaring post-level architecture (opening modes, argument shape by post type, density philosophy, first-person rules, closing modes, off-voice moves). When the file exists and has content, the skill reads it immediately after `persona/voice.md` and it overrides the *Blog Anatomy* section plus the narrative-density doctrine in `references/tone-guide.md`. Personas without the file are unaffected — the generic Blog Anatomy still applies. Originally contributed by @shelajev.
