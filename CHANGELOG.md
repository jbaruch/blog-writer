# Changelog

### Added

- **A structural audit layer above the 39 anti-patterns** (#29) — `references/structural-audits.md` adds six discourse-level audits that work on the shape of the whole post rather than its sentences: theme explicitness, structural tidiness, emotion mode, reference specificity, reader engagement, and shape convergence. Grounded in StoryScope (Russell et al. 2026, arXiv:2604.03136), which classified 61,608 stories using only discourse features at 93.2% macro-F1, then ran the AI text through a professional span-level rewriting pass and watched detection fall 1.6 points. Surface editing is not the durable half, so a draft can pass all 39 patterns and still be identifiable from its skeleton. Reimplemented from the published findings; the paper is cited, not relicensed.
- **The audits split across two altitudes and two phases** — audits 1, 2, and 6 run on the outline at Phase 2 (new section `2f`), where structure is nearly free to change; audits 3, 4, and 5 run on the prose in Phase 3 and 4 alongside the anti-pattern check. This follows the study's own method finding: comparing raw prose surfaces style features while comparing structured outlines surfaces structural ones, with only 6 of the top 20 features overlapping between the two methods. Each audit runs one at a time, since aspect-based checking found 95.4% of features against 68.4% for a single combined pass.
- **`_blog-skill/post-shapes.json` records each finished post's skeleton** — audit 6 is the only audit that cannot be run against a single post in isolation, so it needs history. Schema, field meanings, and both contracts live in `references/post-shapes-schema.md` per `jbaruch/coding-policy: stateful-artifacts`; `blog-writer` is the sole owner, writer, and migrator, and `schema_version` is stamped per record so a partially migrated history still describes itself accurately. It sits beside `series-tracker.md` rather than inside it because convergence is cross-series while the tracker is series-scoped prose.
- **Two scripts own every operation on the shape history** — `check-shape-convergence.sh` reads and compares, `record-post-shape.sh` appends. Parsing JSON, selecting the comparison window, applying the convergence predicate, and stamping records are fixed-input/fixed-output operations, so they belong in tested scripts rather than agent prose (`jbaruch/coding-policy: script-delegation`). The window size, the history minimum, and the convergence predicate are the scripts' decision contract and are referenced rather than restated in the skill (`script-as-black-box`). An absent history exits 0 with `can_fire: false` — the normal first-post state — while an unreadable or malformed one exits 1 with an actionable diagnostic, so a permissions error or corrupt JSON can never be silently read as "no history yet". The writer refuses a history holding records from a newer skill version and leaves it byte-identical, and stages its output beside the destination so an interrupted run cannot truncate an author's history. Every existing record is validated against a shared field contract in `post-shapes-lib.sh` before either script acts, so a history that does not match its schema is refused rather than averaged over by the reader or extended by the writer — a record missing `schema_version` is malformed, not version zero. A history holding any record from a newer plugin version makes the whole history unusable rather than partly readable: the records a lagging install can still parse are the *older* ones, so a verdict built from them would describe the wrong posts while appearing to describe the most recent. The writer keeps the history sorted by `date`, so recording a post finished earlier than one already on file cannot break the reader's newest-last window. Recording is idempotent by slug — a second run for the same post replaces its record and reports `"action": "updated"`, so re-running the step after a late revision corrects the history rather than skewing the window with two records for one post — and the writer is invoked from exactly one place (Step 12), since invoking it from Phase 4 as well would have filed every completed post twice. Both scripts report a dangling symlink rather than letting `-e` collapse a broken link into the absent case. The writer streams the existing history through stdin rather than argv, so a history that grows past the argv size limit still writes; verified against a 4 MB, 3,000-record file. A history reached through a symlink — the shape a synced drive takes, matching how the persona directory already works — is written through to its target, so the link survives rather than being replaced by a regular file. The reader selects its comparison window by `date` rather than by position, so a hand-edited or badly merged history still compares the most recent posts. Duplicate slugs are rejected as ambiguous, since recording is idempotent by slug and two records for one post would let the window count it twice. 76 assertions in `tests/test_post_shapes.sh` cover both scripts, including the exactly-two-records case, each malformed-record shape, the mixed-version history, the backfill ordering, and every refusal path.

### Fixed

- **The three script test suites no longer strand temp directories** — every suite created case directories with `mktemp -d` and never removed them, leaving litter in `TMPDIR` on each run and violating `jbaruch/coding-policy: testing-standards` Independence. Each suite now creates one owned root and removes it in an `EXIT` trap that ends with `return 0`, so cleanup cannot rewrite the suite's exit status. Two suites predate this PR; fixed here rather than left, since a round was already in flight.
- **Test dates are fixed past literals** — two cases used dates that were in the future at the time of writing, which `testing-standards` Determinism forbids outside the live-upstream fixture carve-out. Every date in the suite is now a fixed past literal, and the scripts take the date as an argument rather than reading the clock, so the assertions cannot rot.
- **The per-case stderr file lives under the suite root** — it was created with an unscoped `mktemp`, so an interrupt between creating it and removing it stranded a file the suite's own cleanup contract promised to remove.
- **The new suite no longer switches errexit on globally** — `run_case` restored `set -e` after each case even though the harness runs under `set -uo pipefail`, so from the first case onward every later command ran under an errexit the suite was never written for.

### Changed

- **Audits calibrate against the persona, not a generic human** — every rate in the study compares humans-in-general to AI-in-general, and the author is not humans-in-general. Each audit reads `persona/voice.md` first: where the profile already prescribes the human-side behavior, the audit becomes a drift check rather than a new rule. A persona whose declared devices include parenthetical asides already satisfies audit 5, and enforcing it again would double the dose. Where `persona/framework.md` exists it governs, and audits 2 and 6 read its declared opening and closing modes as the menu to vary across.
- **The blog anatomy is a starting point, not a template** — the fixed eight-part shape was itself a convergence machine, running the same skeleton every post. TLDR and author bio stay fixed schema; everything between them is one arrangement among several, and `blog-anatomy.md` gains opening-mode and closing-mode menus to vary across. "The broader point" is now explicitly optional and named as the first thing to cut: a zoom-out section placed after the story already landed is the epilogue habit, the most distinctive fingerprint of the model doing the drafting.
- **The convergence trap is stated before any audit is applied** — the study's deepest result is that five models occupy one tight region of structural space while human writing is dispersed, with 24.7% of human stories in the corpus's rarest 10% against 7.1% of AI stories. Rarity is the signal, so a checklist applied uniformly builds a new detectable cluster. The guidance is one or two interventions per post, varied across posts, with an audit that finds nothing recorded as a valid result.

## 1.1.26 — 2026-08-11

### Added

- **Anti-pattern #39, body-performance emotion** (#29) — a feeling delivered through the body or the room instead of named: "my stomach dropped", "the cursor blinked mockingly", "something shifted". This is the single largest human-AI gap measured in the StoryScope corpus (Russell et al. 2026, arXiv:2604.03136), which classified 61,608 stories using only discourse-level features: AI performs emotion through the body 81% of the time against 38% for humans, while humans name the feeling outright 29% against 8%. The pattern covers setting-as-mirror, sensory pile-on, the unnamed realization, and deferred naming, and carries a carve-out protecting factual physical detail — the one sock, the cat on the keyboard, the terminal output you actually saw — which is reportage and stays.

### Changed

- **The narrative-density doctrine is scoped, not reversed** (#29) — `tone-guide.md` opened by calling "Show, Don't Summarize" the single biggest quality differentiator, which collides with the finding above. The collision turned out to be narrower than it looked: every "good (specific)" example in that section is a *named, checkable specific* — real terminal output, a real file count — which is the half of the advice where humans beat machines roughly two to one. Only the emotional half inverted. The section now splits the rule explicitly with a push-harder / cut table, and points at #39 for the emotional half rather than restating it. No existing guidance was dropped, and the density rule still governs.
- **The anti-pattern count reads 39 across every surface** — `SKILL.md` frontmatter and reading list, `plugin.json` description, three README claims, the `tone-guide.md` quick index (which gains its 39th entry), and five scan-procedure references in `process.md` and `ai-anti-patterns.md` that name the count in the check itself. A count that disagrees with the file it describes teaches the agent to distrust both.

## 1.1.25 — 2026-08-11

### Changed

- **The ShellCheck tarball is verified before it is unpacked** (#28) — `.github/workflows/test.yml` pinned the release version but trusted the artifact on name alone: `--fail` catches HTTP errors and says nothing about integrity, and the resulting binary runs against every shell script in the repo before the tests, on every pull request. The step now carries `SHELLCHECK_SHA256` beside `SHELLCHECK_VERSION` and checks it with `sha256sum --check --strict`, with a message that distinguishes the two ways it can fail — a forgotten checksum bump after a version bump, versus an artifact that should not be trusted. The checksum renews with the version under the quarterly cadence already documented beside the pin, so it adds no new renewal duty. Raised by Copilot as an advisory on #24 and deferred there under `review-severity` rather than folded into an already-approved PR.

## 1.1.24 — 2026-08-10

### Changed

- **Migrated the plugin manifest from `tile.json` to `.tessl-plugin/plugin.json`** — `summary` becomes `description`, the `skills` map becomes an array, and the manifest declares `private: false` explicitly rather than relying on a default that would make a published plugin private. Residual "tile" wording is reconciled to "plugin" across the publish workflow name, the anti-pattern examples, and `evals/scenario-7/criteria.json`; the `docs.tessl.io` references in `example-persona/product.md` keep "tiles" because those are live external URLs and page titles. `tessl.json` moves `jbaruch/coding-policy` to the `latest` specifier the consumer-manifest carve-out requires.
- **Moved the skill to `skills/blog-writer/` and restructured it into flat steps** — `SKILL.md`, `references/` and `example-persona/` now live in the skill directory the manifest declares. The move brought `SKILL.md` inside `skill-authoring`'s `applyTo` scope for the first time, and the workflow is now `## Step 1` through `## Step 11`: resolve the persona path, probe its state, establish it, onboard, refresh the anti-patterns, read the references, then one step per writing phase. Post shape and series handling moved to `references/blog-anatomy.md`, placeholder handling to `references/process.md` Phase 3, and the anti-pattern check procedure to the top of `references/ai-anti-patterns.md` — SKILL.md is the execution plan, not the reference manual. No instruction text was dropped.
- **Wired the CHANGELOG stamp step into the publish pipeline** — `publish.yml` now passes `stamp-changelog: true`, an input that defaults to `false` and had never been set, so the step silently skipped on every publish this repo has done. That is why entries accumulated under an `## Unreleased` heading `context-artifacts` forbids: auto-bump assigns the version at publish time, so an author cannot write the heading, and un-headed blocks are illegal when nothing stamps them. The heading is gone and the stamp action, which mirrors `tesslio/patch-version-publish`'s version computation, now heads these entries.
- **The Wikipedia freshness fetch is a script** — `skills/blog-writer/fetch-signs-of-ai-writing.sh` replaces an inline `curl` and an instruction to improvise temp-file handling. It carries a documented JSON contract with distinct exit codes (0 fetched, 1 fetch failed, 2 tool error), emits its result through `jq` rather than `printf` so a path containing a quote cannot break the output, downloads into a script-owned staging file and moves it into place only after every validation passes — so a failed fetch never truncates an existing destination — and cleans up under any exit via an EXIT trap, including signals.
- **Persona directory setup is a script** — `skills/blog-writer/setup-persona-dir.sh` replaces an `ln -s` the skill told the agent to reproduce. `--probe` reports `exists`, `kind`, `target` and `voice_ready` as JSON without writing, so the skill routes on that instead of running its own filesystem checks; `voice_ready` distinguishes a directory that exists from onboarding that actually finished. It is idempotent: an established persona is reported `unchanged` and never repointed, and a dangling symlink or occupying file is reported rather than replaced, so re-running cannot orphan an author's voice profile.
- **Both scripts ship with tests that run in CI behind a diagnostics gate** — `.github/workflows/test.yml` runs ShellCheck over every shell script and then every `skills/**/test_*.sh` suite, on each pull request and on `main`; `.github/pre-publish.sh` chains the same two gates into the publish pipeline, so a script whose tests fail cannot reach the registry. Suites are discovered by glob. The tests stub `curl` on `PATH` and isolate `HOME`, so they touch no network, clock, randomness, or real persona. `.tesslignore` keeps them out of the published plugin, verified with `tessl plugin pack`.
- **Synchronised the README with the manifest** — added the Tessl registry badge, a skills table and installation instructions required by `context-artifacts` Plugin Structure, corrected an anti-pattern count that read 32 in two places when there are 38, and reworded a claim that the anti-pattern list "auto-updates" from Wikipedia: the refresh is a step the agent runs, not a background process. The manifest `description` is condensed to one sentence, retaining every discovery and trigger term.

### Fixed

- **Pattern #1 missed the "X rather than Y" variant** (#22) — the reference covered "Not X, but Y" and "Not just X, but also Y" but not the comparative form, which does identical structural work (negation plus affirmation competing for one slot) while reading as measured prose. It is the hardest of the three to catch by eye, because it does not sound like a mic drop. Added the variant to pattern #1 and a literal "rather than" sweep to the Pass 1 mechanical checks.
- **Pass 1 had no mechanical check for pattern #7** (#5) — only #8's em-dash density count existed, so paired em-dashes collapsed into "too many em-dashes" and individual occurrences survived all three passes. Added a #7 sweep that flags every ` — X — ` pair regardless of count, and made #8's entry state that it is the density check only, so a passing count no longer reads as clearing #7.
- **Eval scenario-2 (voice-profile onboarding) was scoring 0/0** — its output spec and all 11 criteria targeted the absolute `~/.claude/blog-writer-persona/` path, which the eval grader (working-directory only) cannot see, so every criterion failed in both baseline and with-context. Redirected outputs to the working directory; the scenario now grades real output (baseline 91 → with-context 100).
