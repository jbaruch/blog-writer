# Changelog

### Changed

- **Migrated the plugin manifest from `tile.json` to `.tessl-plugin/plugin.json`** — `summary` becomes `description`, the `skills` map becomes an array, and the manifest declares `private: false` explicitly rather than relying on a default that would make a published plugin private. Residual "tile" wording is reconciled to "plugin" across the publish workflow name, the anti-pattern examples, and `evals/scenario-7/criteria.json`; the `docs.tessl.io` references in `example-persona/product.md` keep "tiles" because those are live external URLs and page titles. `tessl.json` moves `jbaruch/coding-policy` to the `latest` specifier the consumer-manifest carve-out requires.
- **Moved the skill to `skills/blog-writer/` and restructured it into flat steps** — `SKILL.md`, `references/` and `example-persona/` now live in the skill directory the manifest declares. The move brought `SKILL.md` inside `skill-authoring`'s `applyTo` scope for the first time, and the workflow is now `## Step 1` through `## Step 11`: resolve the persona path, probe its state, establish it, onboard, refresh the anti-patterns, read the references, then one step per writing phase. Post shape and series handling moved to `references/blog-anatomy.md`, placeholder handling to `references/process.md` Phase 3, and the anti-pattern check procedure to the top of `references/ai-anti-patterns.md` — SKILL.md is the execution plan, not the reference manual. No instruction text was dropped.
- **Wired the CHANGELOG stamp step into the publish pipeline** — `publish.yml` now passes `stamp-changelog: true`, an input that defaults to `false` and had never been set, so the step silently skipped on every publish this repo has done. That is why entries accumulated under an `## Unreleased` heading `context-artifacts` forbids: auto-bump assigns the version at publish time, so an author cannot write the heading, and un-headed blocks are illegal when nothing stamps them. The heading is gone and the stamp action, which mirrors `tesslio/patch-version-publish`'s version computation, now heads these entries.
- **The Wikipedia freshness fetch is a script** — `skills/blog-writer/fetch-signs-of-ai-writing.sh` replaces an inline `curl` and an instruction to improvise temp-file handling. It carries a documented JSON contract with distinct exit codes (0 fetched, 1 fetch failed, 2 tool error), emits its result through `jq` rather than `printf` so a path containing a quote cannot break the output, downloads into a script-owned staging file and moves it into place only after every validation passes — so a failed fetch never truncates an existing destination — and cleans up under any exit via an EXIT trap, including signals.
- **Persona directory setup is a script** — `skills/blog-writer/setup-persona-dir.sh` replaces an `ln -s` the skill told the agent to reproduce. `--probe` reports `exists`, `kind`, `target` and `voice_ready` as JSON without writing, so the skill routes on that instead of running its own filesystem checks; `voice_ready` distinguishes a directory that exists from onboarding that actually finished. It is idempotent: an established persona is reported `unchanged` and never repointed, and a dangling symlink or occupying file is reported rather than replaced, so re-running cannot orphan an author's voice profile.
- **Both scripts ship with tests that run in CI behind a diagnostics gate** — `.github/workflows/test.yml` runs ShellCheck over every shell script and then every `skills/**/test_*.sh` suite, on each pull request and on `main`; `.github/pre-publish.sh` chains the same two gates into the publish pipeline, so a script whose tests fail cannot reach the registry. Suites are discovered by glob. The tests stub `curl` on `PATH` and isolate `HOME`, so they touch no network, clock, randomness, or real persona. `.tesslignore` keeps them out of the published plugin, verified with `tessl plugin pack`.
- **Synchronised the README with the manifest** — added the Tessl registry badge, a skills table and installation instructions required by `context-artifacts` Plugin Structure, corrected an anti-pattern count that read 32 in two places when there are 38, and reworded a claim that the anti-pattern list "auto-updates" from Wikipedia: the refresh is a step the agent runs, not a background process. The manifest `description` is condensed to one sentence, retaining every discovery and trigger term.

### Fixed

- **Pattern #1 missed the "X rather than Y" variant** (#22) — the reference covered "Not X, but Y" and "Not just X, but also Y" but not the comparative form, which does identical structural work (negation plus affirmation competing for one slot) while reading as measured prose. It is the hardest of the three to catch by eye, because it does not sound like a mic drop. Added the variant to pattern #1 and a literal "rather than" sweep to the Pass 1 mechanical checks.
- **Pass 1 had no mechanical check for pattern #7** (#5) — only #8's em-dash density count existed, so paired em-dashes collapsed into "too many em-dashes" and individual occurrences survived all three passes. Added a #7 sweep that flags every ` — X — ` pair regardless of count, and made #8's entry state that it is the density check only, so a passing count no longer reads as clearing #7.
- **Eval scenario-2 (voice-profile onboarding) was scoring 0/0** — its output spec and all 11 criteria targeted the absolute `~/.claude/blog-writer-persona/` path, which the eval grader (working-directory only) cannot see, so every criterion failed in both baseline and with-context. Redirected outputs to the working directory; the scenario now grades real output (baseline 91 → with-context 100).

### Removed

- **Retired four no-lift eval scenarios** per `jbaruch/coding-policy: plugin-evals` ("lift, not attainment"), confirmed across two runs: the `blog-writer-framework-override` scenario (contrived, near-zero lift), and scenario-1 / scenario-5 / scenario-6 (anti-pattern cleanup, soul check, tightening) whose baselines run 94–99% — coincidence with universal competence, no headroom for the plugin to show lift. Kept scenarios (0, 2, 3, 4, 7, 8) all contribute positive lift.

### Added

- **Optional `persona/framework.md` for post-level voice overrides** — A persona can now ship a `persona/framework.md` declaring post-level architecture (opening modes, argument shape by post type, density philosophy, first-person rules, closing modes, off-voice moves). When the file exists and has content, the skill reads it immediately after `persona/voice.md` and it overrides the *Blog Anatomy* section plus the narrative-density doctrine in `references/tone-guide.md`. Personas without the file are unaffected — the generic Blog Anatomy still applies. Originally contributed by @shelajev.
